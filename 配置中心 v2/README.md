独立项目目录：`/Users/guanghui/Documents/ChatGPT/AI-EDC`。源自下载目录中的“临研-配置中心 4”，与“临研-个案”分开维护。

## 启动

```bash
python3 -m http.server 4174 --bind 127.0.0.1
```

也可运行 `npm start`。不需要安装依赖或构建。

访视任务预览：http://127.0.0.1:4174/?page=collection&section=tasks

## 项目详情导航

顶部依次为：访视任务、访视管理、关联治疗组、账号映射。

- 访视任务：项目级入口，左侧为任务配置、问卷管理、映射配置。
- 访视管理：查看同步的访视版本及 CRF 详情。
- 原版计划模板代码保留供历史参考，访视版本列表不再承担任务配置入口。

## 任务配置

进入“任务配置”后首先展示版本列表。列表字段为：版本名称、版本、版本说明、项目访视版本、适用分组、任务数量、状态、发布时间和操作。进入某一版本后，左侧按项目访视展示任务数量，右侧展示当前访视关联的任务；多访视任务仅关联展示，不会复制任务数据。从当前访视新增任务时，弹框会默认选中该访视。

新增版本时填写：

- 项目访视版本：必填，从项目同步的访视版本中选择。
- 版本名称：必填且项目内不重复。
- 版本：系统根据现有最高主版本自动生成 V1.0、V2.0、V3.0 等，只读。
- 版本说明：选填。
- 适用分组：通过下拉框多选。

版本草稿可配置任务、发布或删除。发布前至少需要一个完整任务；发布后整版只读，可通过“复制新建”生成下一版草稿。复制会保留版本字段和全部任务，并为任务生成新的内部 ID。

进入版本后维护该版本的任务明细。新增任务弹框支持多选适用访视，采集方式可选择填写已有问卷或上传文件；采集日期支持单次采集、连续天数和指定天数，采集时间可添加多次并分别设置固定时间点或不指定时间。执行窗口会根据日期类型及是否配置固定时间自动使用天或时作为单位，逾期执行默认开启。

## 问卷管理与映射

问卷管理展示项目范围的问卷清单，可通过标题和选填的表单说明新增问卷，系统自动生成问卷 ID 并记录更新时间。已被任一任务配置或任一配置版本映射引用的问卷不能删除。

映射配置仍按所选配置版本保存。左侧仅展示主动添加到映射范围的 CRF，右侧仅展示已配置的字段映射；每个 CRF 字段只能对应一个数据来源字段，当前不配置取值顺序或合并规则。添加、编辑或删除后自动保存。

## 数据存储和迁移

当前为静态交互原型，任务配置版本与项目问卷关联存储在本浏览器 localStorage 的 `ai-edc:collection-config:v3:<项目ID>`，项目之间隔离。CRF 映射继续使用原项目＋访视版本存储键。

首次读取时会从 v2 项目任务配置迁移：

- 原已发布任务组合为“初始任务配置”V1.0 已发布版本。
- 如存在待发布修改，会另建 V2.0 草稿，保留修改后的任务内容。
- 旧存储键保留不删除；v3 数据存在后不再重复迁移。

更早的按访视版本任务存储也会合并迁移。读取到无法识别的数据会停止写入并提示刷新检查。

主要文件：

- `index.html`：项目页面、导航和原型演示数据。
- `visit-tasks.js`、`visit-tasks.css`：任务配置版本、版本内任务及项目问卷关联。
- `data-sources.js`、`data-sources.css`：CRF 数据来源映射。
- `assets/`、`.design-notes/`：原素材及历史设计说明。

原始文件备份位于 `.backups/`；带设计说明的两个历史 HTML 未修改。

## 原型边界

仅 SYX-ML46252 预置演示问卷及数据来源字段字典。分组、问卷版本及配置版本均为演示数据；原始 `visitCrfData` 尚未按版本拆分，因此各配置版本暂共用同一份访视／CRF 清单，映射存储仍按所选版本隔离。正式对接时需使用真实的配置版本、CRF 字段变量、问卷字段变量及研究分组接口。

发布只保存本地配置，不生成患者任务、不发送通知、不迁移患者适用版本、不执行 AI 预填。
