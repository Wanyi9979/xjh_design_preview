## 启动

```bash
python3 -m http.server 4174 --bind 127.0.0.1
```

也可运行 `npm start`。不需要安装依赖或构建。

采集配置预览：http://127.0.0.1:4174/?page=collection&section=tasks

## 项目详情导航

顶部依次为：访视管理、采集配置、关联治疗组、账号映射。

- 访视管理：查看同步的访视版本及 CRF 详情。
- 采集配置：项目级入口，左侧为采集任务、问卷管理、映射配置。
- 原版计划模板代码保留供历史参考，访视版本列表不再承担采集任务配置入口。

## 采集任务版本

进入“采集任务”后首先展示版本列表。列表字段为：版本名称、版本、版本说明、所属访视版本、适用分组、任务数量、状态、发布时间和操作。

新增版本时填写：

- 所属访视版本：必填，从项目同步的访视版本中选择。
- 版本名称：必填且项目内不重复。
- 版本：系统根据现有最高主版本自动生成 V1.0、V2.0、V3.0 等，只读。
- 版本说明：选填。
- 适用分组：选填；未选择时表示全部组。

版本草稿可配置任务、发布或删除。发布前至少需要一个完整任务；发布后整版只读，可通过“复制新建”生成下一版草稿。复制会保留版本字段和全部任务，并为任务生成新的内部 ID。

进入版本后维护该版本的任务明细。任务支持问卷、电子日记卡、院外资料上传，执行方式包括按访视、周期采集和按需填写。版本层适用分组控制整套配置的使用范围；任务层仍可配置版本范围内的全部组或指定组，以支持不同分组执行不同任务。

## 问卷管理与映射

问卷管理是项目范围的关联清单，从演示问卷库选择并固定内容版本，不复制表单。已被任一采集任务版本或任一访视版本映射引用的问卷不能移除。

映射配置仍按所选访视版本保存，页面右上角选择访视版本后配置目标 CRF。切换版本或离开时保护未保存修改。映射草稿和已发布配置分别保存。

## 数据存储和迁移

当前为静态交互原型，采集任务版本与项目问卷关联存储在本浏览器 localStorage 的 `ai-edc:collection-config:v3:<项目ID>`，项目之间隔离。CRF 映射继续使用原项目＋访视版本存储键。

首次读取时会从 v2 项目采集配置迁移：

- 原已发布任务组合为“初始采集任务配置”V1.0 已发布版本。
- 如存在待发布修改，会另建 V2.0 草稿，保留修改后的任务内容。
- 旧存储键保留不删除；v3 数据存在后不再重复迁移。

更早的按访视版本任务存储也会合并迁移。读取到无法识别的数据会停止写入并提示刷新检查。

主要文件：

- `index.html`：项目页面、导航和原型演示数据。
- `visit-tasks.js`、`visit-tasks.css`：采集任务版本、版本内任务及项目问卷关联。
- `data-sources.js`、`data-sources.css`：CRF 数据来源映射。
- `assets/`、`.design-notes/`：原素材及历史设计说明。

原始文件备份位于 `.backups/`；带设计说明的两个历史 HTML 未修改。

## 原型边界

仅 SYX-ML46252 预置演示问卷。分组、问卷版本及访视版本均为演示数据；原始 `visitCrfData` 尚未按版本拆分，因此各访视版本暂共用同一份访视／CRF 清单，映射存储仍按所选版本隔离。正式对接时需使用真实的访视版本、CRF ID、项目问卷及研究分组接口。

发布只保存本地配置，不生成患者任务、不发送通知、不迁移患者适用版本、不执行 AI 预填。
