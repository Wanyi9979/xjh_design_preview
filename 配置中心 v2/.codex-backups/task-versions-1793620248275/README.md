```bash

```

也可运行 `npm start`。不需要安装依赖或构建。

采集配置预览：http://127.0.0.1:4174/?page=collection&section=tasks

## 项目详情导航

顶部依次为：访视管理、采集配置、关联治疗组、账号映射。

- 访视管理：查看同步的访视版本及 CRF 详情。
- 采集配置：项目级入口，左侧为采集任务、问卷管理、映射配置；不再放在某个访视版本内。
- 原版计划模板代码保留供历史参考，版本列表中的模板／任务配置入口已移除。

## 采集任务

任务列表支持任务名称、适用访视版本、分组、执行方式及状态筛选。支持新建、草稿编辑、发布、查看、创建新版、版本记录、删除未发布草稿和撤销新版草稿。

任务版本与访视版本分别管理：

- 每个任务首次发布为 V1.0，创建新版依次使用 V2.0、V3.0 等自动版本号。
- 新建／编辑时必须选择一个适用访视版本，任务版本不跟随访视版本号变化。
- 修改已发布任务形成下一版草稿；保存草稿不会覆盖当前已发布版本。
- 每次发布保留完整历史快照，可查看各次使用的访视版本、问卷内容版本、分组及执行规则。
- 问卷被任何任务草稿、已发布版本、历史版本或任意访视版本的映射引用时，不允许移除项目关联。

执行方式支持按访视、周期采集和按需填写。按访视支持多个访视及相对计划访视日的开放／截止偏移；周期采集支持每天／每周、开始结束条件和当次截止时间；按需填写支持开放期间多次填写。

## 问卷管理与映射

问卷管理是项目范围的关联清单，从演示问卷库选择并固定内容版本，不复制表单。映射配置仍按所选访视版本保存，右上方的访视版本选择器确定目标 CRF 范围；切换版本或离开时保护未保存的修改。CRF 映射支持保存草稿、发布，原已发布映射与草稿分开保存。

## 数据存储和迁移

当前是静态交互原型，任务和问卷关联存储在本浏览器 localStorage 的 `ai-edc:collection-config:v2:<项目ID>`，项目之间隔离。CRF 映射继续使用原项目＋访视版本存储键。

首次读取新版任务时合并旧 `ai-edc:visit-tasks:v1:<项目ID>:<访视版本>` 数据，保留各自适用访视版本，使用带来源版本前缀的任务 ID 避免冲突；已发布内容转换为任务 V1.0，若有待发布草稿则转换为 V2.0 草稿。下一次保存写入新版存储，旧键保留不删除。新版数据存在后不再从旧键重新合并。迁移遇到无法识别的数据会停止写入，并提示刷新检查。

原始文件备份位于 `.backups/`；带设计说明的两个历史 HTML 未修改。主要文件：

- `index.html`：项目页面、导航和原型演示数据。
- `visit-tasks.js`、`visit-tasks.css`：采集配置、任务版本、项目问卷关联及页面样式。
- `data-sources.js`、`data-sources.css`：CRF 数据来源映射。
- `assets/`、`.design-notes/`：原素材及历史设计说明。

## 原型边界

仅 SYX-ML46252 预置演示问卷与五个任务。分组、问卷版本及访视版本均为演示数据；原始 `visitCrfData` 尚未按版本拆分，因此各访视版本暂共用同一份访视／CRF 清单，配置存储仍按所选版本隔离。正式对接时需接入各版本真实访视及 CRF ID、项目问卷接口和研究分组接口。

发布只保存本地配置，不生成真实患者任务、不发送通知、不迁移患者适用版本、不执行 AI 预填。原页面的 Figma 捕获辅助脚本加载需要网络。
